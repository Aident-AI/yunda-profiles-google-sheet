# Fixed CLI renderer

This companion implements the frozen snapshot and direct-page rendering contract. It performs no network calls and holds no credentials. Use Loadout for Sheet and Drive access. A host agent still owns fact extraction, faithful translation, user decisions, photo orientation, final visual/privacy inspection and verified Drive delivery.

## Runtime

Use Node.js 22 or later. From the installed companion directory, run `pnpm install --frozen-lockfile --ignore-scripts` once. Reuse an already installed matching runtime. Dependencies are pinned in package.json and pnpm-lock.yaml. Do not install the abandoned Yunda application or start a server.

## Prepare

Create a private snapshot JSON using every member and normalization rule in [the export contract](export-contract.md). `fields.json` is the fixed 74-key export allowlist; internal fields never belong in this input. Fill all display_values explicitly, including empty strings. All leaf values are strings. Include any translated and derived display text before freezing. The renderer checks completeness and source states, but the agent must verify that translations and derived values preserve the original facts.

Run `node scripts/render.mjs prepare /private/path/snapshot.json`. The result gives the canonical SHA-256, revision, language and exact omissions. Record an explicit user approval for those omissions, or collect missing inputs and prepare again. Do not fabricate approval. No PDF is generated by prepare.

## Render

Create a private job JSON containing:

- `snapshot`: the complete prepared snapshot object.
- `export_id`: the one allocated UUID, reused for recovery.
- `authorization`: when blanks are present, `snapshot_sha256`, string `profile_revision`, `language`, the exact `omissions` array and the user's `instruction`. Store actual message time separately when known.
- `assets`: `master`, `map` and `font` are local filenames of hash-verified private inputs. `photos` maps each selected role to its local orientation-normalized PNG file. Normalize user-approved images before freezing and hash those exact bytes. Do not use synthetic photos in a real profile.
- `output_dir`: a private local working directory outside the installed Skill tree.

Run `node scripts/render.mjs render /private/path/job.json`. It writes one seven-page PDF, the canonical private snapshot and a fit/checksum report. Its stdout deliberately includes no answers or contact details. The report status is `rendered-needs-visual-and-privacy-verification`: it is not an export-success claim.

Inspect the PDF's text and all rendered pages using the host's PDF tools, as required by the contract. Then upload the exact bytes through Loadout, verify the final private Drive file, deliver its webViewLink immediately, and finish the single Sheet batch/readback. Never give the user local output paths. Do not put snapshots or reports into the PDF.

## Failures and retry

The renderer rejects mismatched asset hashes, unknown/private keys, duplicate fields, stale approval, unresolved nonblank values, wrong page boxes, invalid rectangles, missing glyphs and overflow. Correct the affected input with the user or report a template/runtime issue. Do not patch code speculatively during an export. If the output filename already exists, inspect and reuse the exact passing file and recovery state; the renderer refuses to overwrite it. Rendering-only repairs use a separate private attempt directory until a passing file is selected, preserving the same input snapshot and export UUID.

## Maintenance checks

Run `pnpm test` for snapshot/approval, privacy, map/coordinate and fit regressions. Release verification also needs both languages on the actual approved seven-page template, approved blanks, and three synthetic image slots. Customer files are private test inputs and must never enter the source or release archive.
