# Export: "Make the PDF"

Ask unresolved choices in one question: **"English or Chinese-English? With Yunda watermark or without watermark?"** Use `en` or `zh-en` for language, and `yunda` or `none` for watermark. Reuse the user's current explicit choice or stated persistent preference. Do not add another confirmation for an already selected option. Generate only the requested combination; two or four versions require a request for those outputs. Follow the selected approved template exactly.

The no-watermark sample retains the seven-page beige/purple layout, bilingual section labels, table and photo positions, partner logos and generic guidance footer. It omits Yunda's company title/logo and company contact/website footer. Its cover says "Surrogate Profile". This is not a request to remove partner logos, candidate data, or all artwork. Use its separately reviewed blank master and map, not white paint over an existing branded or filled PDF.

The deliverable is a **verified private Google Drive PDF link**. A sandbox file is an intermediate artifact, not customer delivery. Never put `/workspace`, `/tmp`, `/mnt/data`, `file://`, a temporary upload URL or an unverified URL in the customer response.

Read this document only when the user requests a PDF. Validation is mandatory inside export, never a separate tool. Read [the export and rendering contract](export-contract.md) once for this exact Skill revision before the first export; reuse it during the session. It defines the frozen snapshot, direct-page rendering, verification and recovery order. Hosted Skill reads provide these instructions, not an installed executable renderer. Do not claim a companion script was installed or supplied.

1. **Read once and collect decisions together.** Batch the bounded Profiles, Answers, Files and Setup ranges, using spreadsheet metadata's multiple-range support when available. When the profile was just imported or updated and read back in this same uninterrupted operation, reuse that exact verified snapshot; read only missing Files/Setup data. After waiting for user input or any sign of another editor, refresh the affected source values before freezing. Reuse verified schemas and permissions from this session unless changed or denied. List the missing groups, confirm the public display name and unresolved language/watermark choices, and offer to wait or leave those exact fields/photos blank for this export. Reuse an explicit current choice or approval. Never bypass access, identity, privacy or unsafe/missing templates. Do not infer negative medical answers.
3. **Save approved input corrections before rendering.** If the user supplied a display name, language or other correction, reread affected source cells/revision, apply all confirmed changes coherently, increment revision once and read back. Do not increment for an unchanged value. An approval given alongside those changes applies to the exact stated resulting values and omissions; recording them does not require asking again. Do not repeatedly switch PDF libraries, merge independently sized overlay documents, or rerender an unchanged passing output. Rendering details and security jargon stay out of customer updates.
6. **Upload and immediately deliver the Drive link.** Once the PDF passes, upload those exact bytes to the configured private output folder. Verify provider file ID, filename/export UUID, PDF MIME type, byte length, destination, current-user access and restricted permissions; compare checksums when provided. Return the verified Drive `webViewLink` immediately. Never make the file public. If upload fails, say which step failed and retain private recovery state; do not replace the requested deliverable with a local path. Sheet logging or styling must not delay this link.
7. **Finish bookkeeping with one batch and one readback.** Recheck source inputs against the frozen snapshot. Locate the export UUID before writing, reuse a matching row or reserve a verified empty row, and save the export record together with Profiles status/latest_pdf if still current. If inputs changed, record Historical and leave the newer profile's latest_pdf untouched. Record omissions, authorization, template identity, watermark mode and snapshot hash. Store watermark in the structured authorization metadata even when no omissions exist. Do not add an Answers field, require a new column, or increment profile revision just for this output option. Never infer a historical export's mode merely from a missing field. Read back both rows. Do not rewrite answer values or increment the revision merely to record an export.

Continue bookkeeping in the same active run when the host supports an intermediate response. If it allows only a final response, finish the bounded bookkeeping and return the Drive link there. A verified Drive upload with Sheet sync pending is usable delivery; a local-only file is not. Never promise background work after ending a turn without an actual supported job. On failure retain the same export UUID, snapshot and verified file identity; retry the failed step without regenerating an unchanged PDF or duplicating a file/row. Do not claim a successful sync until readback.

Do not claim clinical verification, template acceptance or a completion time not measured. Do not send the PDF to third parties or change sharing without the user's instruction.

## Exact template rendering procedure

Use the selected variant's authorized sanitized blank master and matching JSON rectangle map, plus the shared embeddable CJK font and license in Setup. Read [variant selection keys](workbook.md#template-variants) and verify the selected template/map/font SHA-256 values against current Setup. Do not silently substitute the branded master when the no-watermark master is missing. These are private data inputs, never executable code. A filled candidate PDF painted white is not a safe blank master. Preserve the seven original page boxes, vector artwork and template positions.

Follow [the fixed direct-page rendering contract](export-contract.md#direct-page-rendering). It specifies one coordinate system, measured text fitting, photo placement and checks. The host needs PDF editing and inspection tools; establish that once before starting. Do not ask customers to install the abandoned Yunda repository. If the host lacks a required runtime, report that limitation rather than promise an exact-layout PDF.
